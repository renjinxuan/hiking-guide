# 「徒步图鉴」微信小程序 — 最小 MVP 文档

> 版本：v1.1（最小 MVP，含轻量广场）
> 说明：本文档是**最小可验证版本**，做「图片 AI 标注 + 个人图鉴 + 轻量广场」三个核心。社交互动（评论/点赞/关注）、AI 成片（配文/配乐）均为**第二阶段**，本阶段只预留接口/埋点，不实现。
> 完整蓝图见《徒步小程序MVP需求文档.md》。

---

## 一、最小 MVP 要验证的核心问题

**要验证的假设：**

> ① 徒步用户愿不愿意用"AI 标注"把风景照变成带地理知识的、更好看的图？（**先用免费验证"有没有人用"**）
> ② 用户愿不愿意把自己的作品发布到广场，以及愿不愿意浏览他人的作品？

**MVP 基调：先免费跑通、验证用户量为主，不一开始做付费。** 假设①先验证"愿不愿意用"（免费），付费意愿（"愿不愿意掏钱"）留到跑通后再验证。假设②成立，则内容平台有冷启动可能。**最小 MVP 用最轻的方式同时验证这两个假设，其他全部砍掉。**

## 二、最小 MVP 范围（只做这些）

### 2.1 核心功能（主线 + 轻量广场）

```
拍照/选图 → 选标注模式 → AI 标注 → 成图 → 保存/发朋友圈 → 存入个人图鉴
                                                        ↘（可选）发布到广场
```

### 2.2 明确要做的（6 个模块）

| 模块 | 说明 |
| --- | --- |
| 1. 用户登录 | 微信一键登录 |
| 2. 照片拍摄 | 拍照/选图，获取 GPS 定位（尽量） |
| 3. AI 标注 | 两种模式：①位置标注（免费）②AI 地理标注（付费点） |
| 4. 成图 | 标注照片 + 位置小图合成，保存相册/发朋友圈 |
| 5. 个人图鉴 | "我的"里能看到自己积累的标注照片列表 |
| 6. 轻量广场 | 浏览他人发布的标注照片 + 发布自己的（可选）+ 点开看详情 |

### 2.2.1 轻量广场（务必保持最简）

**做：**

- 用户可**选择**把标注照片发布到广场（默认只存个人图鉴，发布是可选动作）
- 广场按**时间倒序**列表展示大家发布的作品
- 可**点开**查看某张作品的详情（大图 + 标注）

**不做（避免膨胀）：**

- ❌ 评论、点赞、关注
- ❌ 推荐算法（只按时间倒序，最简单）
- ❌ 留言、找搭子、社交互动
- ❌ 分类、搜索、话题

> 本质：广场是"一个公开的作品流"，让用户能看到别人的图、也让自己的图能被看到。是内容平台的雏形，但**不含任何社交互动功能**。

### 2.3 明确不做（全部砍掉/延后）

- ❌ 社交、加人、找搭子
- ❌ 配文、配乐、AI 成片
- ❌ 路线轨迹记录（不做，或仅做极简兜底）
- ❌ GPX 导入
- ❌ 关注/评论/点赞/私聊
- ❌ 推荐算法
- ❌ 广场的分类/搜索/话题

### 2.4 只留接口/埋点（不实现，为第二阶段预留）

- 数据表预留 `comments`、`follows` 等社交字段（或先不建表，仅留扩展注释）
- 埋点预留：分享按钮、朋友圈分享事件、广场浏览/发布行为（为后续社交/成片分析留数据）
- 会员/订阅字段预留（`plan`、`expire_at`），先做免费/付费分层逻辑，支付延后

## 三、核心功能详细定义：AI 标注

### 3.1 两种标注模式（务必实现）

| 模式 | 场景 | 内容 | 是否用 AI | 收费 |
| --- | --- | --- | --- | --- |
| ① 位置标注 | 自拍/人物/随手拍 | 照片 + 地理位置 + 位置小图 | ❌ | 免费 |
| ② AI 地理标注 | 地貌/山/峡谷/岩石 | 照片 + AI 地理科普标注 + 位置 | ✅ | 付费点 |

### 3.2 AI 标注 JSON 结构（务必按此）

```json
{
  "summary": "一句话概述地貌特征",
  "annotations": [
    {
      "id": "a1",
      "type": "box",
      "x": 0.32,
      "y": 0.28,
      "w": 0.20,
      "h": 0.15,
      "angle": 45,
      "title": "为什么山崖是一层一层的？",
      "term": "沉积岩层理构造",
      "detail": "岩石按不同时期一层层堆积形成。",
      "color": "#3B82F6"
    }
  ]
}
```

### 3.3 AI 标注模型（已实测确定）

- 首选 `glm-5.3-flash`（实测效果好，成本 x0.08，maxAllowedSize 1MB）
- **不要用 **`glm-4.6v`（实测报错，maxAllowedSize 仅 128KB）
- 调用前用 `cloud.llm.models.list()` 动态选 `supportsImages === true` 的模型，不硬编码

### 3.4 两套 Prompt（免费科普版 / 付费专业版）

**科普版（免费）**：通俗语言、基础地貌、面向大众
**专业版（付费）**：专业术语、成因解析、深度地质分析

（完整 Prompt 见完整文档 2.6）

## 四、页面结构（最小 MVP，8 页）

| 页面 | 路径 | 说明 |
| --- | --- | --- |
| 登录页 | pages/login/login | 微信登录引导 |
| 首页/我的图鉴 | pages/index/index | 我的标注照片列表 + 拍照入口 |
| 照片拍摄 | pages/photo/shoot | 拍照/选图，获取定位 |
| 选标注模式 | pages/annotate/mode | 位置标注 / AI 地理标注 二选一 |
| AI 标注结果 | pages/annotate/result | 标注图预览 + 编辑 + 保存/分享/发布到广场（可选） |
| 广场 | pages/square/square | 浏览他人发布的作品（时间倒序）+ 点开详情 |
| 作品详情 | pages/square/detail | 查看某张作品大图 + 标注 |
| 我的 | pages/mine/mine | 个人中心（会员状态、设置） |

### 底部 TabBar（3 个）

1. **图鉴**（我的标注照片）
2. **广场**（浏览他人作品）
3. **我的**

> 说明：拍照入口放在"图鉴"页顶部的主按钮。广场是纯浏览（时间倒序 + 点开详情），无评论/点赞/关注。

## 五、技术方案（与完整文档一致，只取需要的部分）

### 5.1 总体架构

- 前端：微信小程序原生
- 后端：WorkBuddy 云服务（数据库 + 登录 + 存储 + LLM）
- 地图：微信内置 map 组件（位置小图用）
- AI：glm-5.3-flash 多模态模型

### 5.2 数据库（最小 MVP 需 3 张表）

**photos（照片表）**

```
id BIGINT IDENTITY PRIMARY KEY
owner_id TEXT NOT NULL DEFAULT auth.uid()
storage_path TEXT
lat NUMERIC
lng NUMERIC
taken_at TIMESTAMPTZ
annotation_mode SMALLINT        -- 1位置标注 | 2 AI地理标注
location_label TEXT             -- 位置标注文案
ai_annotation JSONB             -- AI标注结果
annotation_status SMALLINT      -- 0未标注 | 1标注中 | 2已标注 | 3失败
is_public BOOLEAN DEFAULT false -- 是否发布到广场
created_at TIMESTAMPTZ DEFAULT now()
```

**posts（广场发布表，可选发布用）**

```
id BIGINT IDENTITY PRIMARY KEY
owner_id TEXT NOT NULL DEFAULT auth.uid()
photo_id BIGINT REFERENCES photos(id)  -- 关联的照片
title TEXT                              -- 可选标题
created_at TIMESTAMPTZ DEFAULT now()
```

**用户会员表（预留，先做分层逻辑）**

```
user_id TEXT
plan SMALLINT                   -- 0免费 | 1月卡 | 2年卡
expire_at TIMESTAMPTZ
```

> RLS 数据隔离：`owner_id = auth.uid()`，前端不手动传 owner\_id。
> posts 表：公开的 posts 允许所有登录用户读，只有 owner 能写/删。
> 社交相关表（comments/follows）本阶段**不建**，仅留扩展说明。

### 5.3 关键实现要点

- LLM 调用：`stream: true` + 首条 `system` message + 图片 `image_url` 传入
- 图片必须先压缩（边长 ≤1280px、体积 ≤500KB）
- 微信登录：`wx.login` + `signInWithWechat(code, appid)`，appid 动态获取

## 七、最小 MVP 验收标准

- [ ] 微信一键登录成功
- [ ] 拍照/选图能获取照片
- [ ] 可选择「位置标注」或「AI 地理标注」
- [ ] AI 标注能生成带地理标注的图（实测通过）
- [ ] 标注可拖动/增删/改文案
- [ ] 成图可保存相册、发朋友圈
- [ ] 「我的图鉴」能看到自己积累的标注照片
- [ ] 可（可选地）把照片发布到广场
- [ ] 广场能按时间倒序浏览他人作品、点开看详情
- [ ] 数据按用户隔离

---

## 八、明确的边界（红线，避免过度开发）

1. **广场只做最简**（浏览 + 可选发布 + 点开详情），**不做评论/点赞/关注/推荐**
2. **不做社交、不做成片**（配文/配乐）——这些是第二阶段
3. **不做路线轨迹记录**（除非极简兜底）
4. **不做支付**（先做免费/付费分层逻辑，会员字段手动设置验证）
5. **不碰微信违规**（不做跳转加好友/建群、不做诱导分享）

> 最小 MVP 的唯一目标：**验证"用户愿不愿意用 AI 标注、愿不愿意付费、愿不愿意发布到广场"这几个核心假设。** 其他一切都可以等。
